### Style Consistency Guidelines
**Color Palette (Hex Codes):**
- Background: Dark grey `#2b2b2b` (matches Blender's default theme)
- Selection highlight: Bright orange `#ff8c00` 
- Wireframe: Cyan `#00ffff` or white `#ffffff`
- Normals: Bright blue `#0080ff`
- Grid major lines: Dark grey `#404040`
- Grid minor lines: Light grey `#2f2f2f`
- Warning/problem: Red `#ff0000`
- Success/good: Green `#00ff00`
- Annotations: White `#ffffff` with semi-transparent backgrounds

**Blender Version:** 
- Use Blender 4.0 interface for all screenshots
- Default dark theme throughout
- Consistent icon style and menu layouts

**View Angles:**
- Use standard orthographic views when showing alignment (Front, Right, Top)
- 45-degree perspective for general demonstrations
- Close-ups for detail work with zoom level that shows geometry clearly

**Selection Highlighting:**
- Selected objects/elements: Bright orange outline
- Active elements: Brighter/thicker orange
- Unselected reference: White or grey wireframe
- Ghost/transparent: 30-50% opacity

**Typography:**
- Interface text: Blender's default UI font
- Annotations: Sans-serif, high contrast against background
- Labels: 14-18pt for readability
- Minimum text size that's readable at 1920px width

**Annotation Style:**
- Arrows: Solid white or orange, 2-3px thickness
- Leader lines: Straight or curved as appropriate
- Callout boxes: Semi-transparent dark background with white text
- Highlight boxes: Orange `#ff8c00` with 50% opacity fill

**Wireframe Clarity:**
- Edge visibility: Ensure wireframes are clearly visible against background
- Line thickness: 1-2px for edges
- Selected edges: Thicker (3-4px) in orange
- Overlapping geometry: Use slight transparency to show layers

- Minimum contrast ratio of 4.5:1 for text

- Orange highlights on dark backgrounds provide excellent contrast
- White text with semi-transparent dark backgrounds for readability

**Text Size:**
- Minimum 14pt for body text in diagrams
- 18-24pt for headers and important labels
- Interface text should match Blender's readable default sizes
- Ensure text remains legible when viewed at 50% zoom

**Diagram Simplicity:**
- Focus on one concept per image when possible
- Avoid cluttering images with too many annotations
- Use progressive disclosure (show steps separately rather than all at once)
- Keep backgrounds uncluttered to emphasize key elements
- Remove unnecessary UI elements from screenshots

### Technical Specifications
**Screenshot Resolution:**
- Minimum 1920x1080 for full viewport screenshots
- 1200x800 minimum for focused demonstrations
- Higher resolution for detail work (zoom-in shots)
- Maintain aspect ratio appropriate to content

**Image Format:**
- **PNG** for screenshots with UI elements (lossless, supports transparency)
- **SVG** for diagrams, flowcharts, reference sheets (scalable, tiny file size)
- **JPG** only if PNG file size is excessive and no transparency needed
- Never use JPG for images with text or sharp lines

**File Size Target:**
- PNG: Aim for under 500KB per image (optimize with tools like pngquant)
- SVG: Should be under 50KB (text and vectors compress excellently)
- Maximum 1MB for any single image
- Optimize images without sacrificing clarity

**Compression:**
- PNG: Use lossless compression tools (pngcrush, optipng, pngquant)
- SVG: Minify and remove unnecessary metadata
- Balance file size with visual quality
- Test compressed versions to ensure no visible artifacts

**Responsive Sizing:**
- Images should scale well from mobile (360px) to desktop (1920px+)
- SVGs handle this perfectly
- PNGs should be large enough to remain clear at 1920px width
- Consider providing thumbnail versions for grid layouts
- Test on various screen sizes before finalizing
