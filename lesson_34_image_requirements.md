## Style Consistency Guidelines

### Color Palette Standards
- **Background:** Dark grey (#2b2b2b) for all technical images
- **Primary highlight:** Bright orange (#ff8c00) for selections and important UI elements
- **Success/confirmation:** Green (#4CAF50) for correct methods, positive outcomes
- **Warning/problem:** Red (#f44336) for errors, issues to avoid
- **Information:** Blue (#2196F3) for informational callouts
- **Wireframe/mesh:** Cyan (#00BCD4) or white for 3D geometry edges
- **Force fields/helpers:** Semi-transparent with distinctive colors (wind=cyan, gravity=white)

### Blender Version Consistency
- Use Blender 4.0+ interface for all screenshots
- Consistent dark theme throughout
- Same icon set across all UI captures

### View Angles and Camera Settings
- **Default viewport angle:** Three-quarter view (approximately 45° from side, 30° from top)
- **Technical diagrams:** Direct orthographic views when showing measurements
- **UI screenshots:** Straight-on capture, no perspective distortion
- **Comparison images:** Identical camera angles across panels for fair comparison

### Selection Highlighting Standards
- Selected objects: Bright orange outline (#ff8c00)
- Active UI elements: Green highlights (#4CAF50)
- Problem areas in troubleshooting: Red highlights (#f44336)
- Use consistent outline weight (2-3 pixels)

### Typography for Labels
- Font: Clear sans-serif (Roboto, Open Sans, or Blender's default UI font)
- Label size: Large enough to read at 1920px width
- Callout boxes: Semi-transparent background with contrasting text
- Arrow style: Simple, clear, with consistent thickness

### Annotation Style Standards
- Arrows: Solid lines with clear heads, orange (#ff8c00) for primary callouts
- Boxes/circles: 2-3 pixel stroke, semi-transparent fill when highlighting areas
- Leader lines: Thin lines connecting labels to UI elements
- Avoid cluttered annotations - maximum 3-4 callouts per image

### Viewport Display Settings
- Solid shading for most technical screenshots
- Material preview for showing cloth appearance
- Wireframe overlay when showing geometry detail
- Consistent lighting across viewport captures (default or 3-point)
- Show floor grid for spatial reference

## Accessibility Considerations

### Color Blindness Accommodations
- Don't rely solely on color to convey information
- Use patterns, textures, or labels in addition to color coding
- Red/green comparisons should also include icons or text labels
- Provide high contrast between elements (4.5:1 minimum ratio)

### Text Legibility
- All text labels should be readable at standard web sizes (min 14px)
- High contrast between text and background
- Avoid placing text over busy backgrounds
- Include alt text descriptions for all images in final implementation

### Visual Hierarchy
- Most important elements should be most prominent
- Use size, color, and position to guide attention
- Don't overcomplicate images with too many elements
- One primary focus per image when possible

### Screen Reader Considerations
- Diagrams should have detailed alt text explaining relationships
- Flowcharts should be described in linear reading order
- Comparison images should describe what's being compared and the difference
- UI screenshots should describe location and purpose of highlighted elements

## Technical Specifications

### Screenshot Resolution
- **Minimum resolution:** 1920 x 1080 (Full HD)
- **Preferred resolution:** 2560 x 1440 (2K) for detail retention when scaled
- **UI screenshots:** Capture at native resolution, scale appropriately
- **Render outputs:** High resolution (2K-4K) for quality, display at web-appropriate sizes

### Image Formats
- **PNG:** Use for:
  - Screenshots with transparency needs
  - Rendered images requiring lossless quality
  - UI captures with text that must remain crisp
  - Images with sharp edges and solid colors
- **SVG:** Use for:
  - Diagrams, flowcharts, technical illustrations
  - Any image that benefits from infinite scalability
  - Simple vector graphics with text and shapes
- **JPG:** Use only if:
  - File size is critical and PNG is too large
  - Photographic renders without transparency
  - Compression artifacts won't affect usability

### File Size Targets
- **Individual images:** Maximum 500 KB for PNG, 100 KB for SVG
- **High-detail renders:** Up to 1 MB if necessary for quality
- **Compression:** Use lossless compression tools (OptiPNG, SVGO)
- **Total page weight:** Target under 5 MB for all images combined

### Responsive Sizing Considerations
- Images should be viewable on mobile devices (320px minimum width)
- Provide srcset for different resolutions when possible
- Critical details should be visible even when scaled down 50%
- Consider creating mobile-optimized versions of complex diagrams

### Image Optimization
- Compress PNG files after creation
- Minify SVG files
- Strip EXIF data from renders
- Use appropriate color depth (8-bit for most, 24-bit for renders with gradients)
