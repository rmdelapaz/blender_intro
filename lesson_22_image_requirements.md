### Style Consistency Guidelines
- **Color Palette:**
  - Background (dark scenes): #2b2b2b
  - Background (light diagrams): #f0f0f0
  - Selection/Focus highlight: #ff8c00 (bright orange)
  - Technical lines: #00bcd4 (cyan)
  - Success/Good: #4CAF50 (green)
  - Warning/Problem: #ffc107 (yellow) or #ff5252 (red)
  - Bokeh/highlights: Soft white/yellow gradients
  
- **Blender Version:** Blender 4.0+ interface for all screenshots (dark theme)
- **View Angles:** 
  - Technical diagrams: Top-down or side-view for clarity
  - 3D scenes: Slight angle (30-45°) for depth perception
  - UI screenshots: Straight-on, clearly readable
  
- **Selection Highlighting:** 
  - Orange outline (#ff8c00) for selected objects
  - Orange wireframe for camera visualization
  - Yellow cross for focus plane indicator
  
- **Typography:** 
  - Sans-serif fonts (Inter, Roboto, or similar)
  - Labels: 16-20pt for readability
  - Annotations: 14-16pt
  - Diagram text: 18-24pt for primary labels
  
- **Annotation Style:** 
  - Leader lines: Thin, orange or white with subtle drop shadow
  - Callout boxes: Semi-transparent dark grey (#333333aa) with white text
  - Numbered annotations: Circled numbers in orange
  - Arrows: Simple, bold, pointing clearly to target

### Accessibility Considerations
- **Color Blindness:** Don't rely solely on color to convey information; use labels, patterns, and shapes
- **High Contrast:** Ensure text has minimum 4.5:1 contrast ratio with backgrounds
- **Text Size:** Minimum 14px for body text in images, 18px for critical labels
- **Alternative Text:** Provide descriptive alt text for each image in HTML:
  - Image #1: "Diagram showing three depth of field zones: foreground blur, focal plane sharp zone, and background blur"
  - Image #2: "Side-by-side comparison of shallow DoF at f/1.8 versus deep DoF at f/16"
  - (Continue for all images with accurate, descriptive alt text)
- **Screen Reader Compatibility:** Ensure SVGs have title and desc elements
- **Zoom Compatibility:** SVG diagrams scale infinitely; PNG/JPG images minimum 1920x1080 for detail

### Technical Specifications
- **Screenshot Resolution:** 1920x1080 minimum (or higher for retina displays)
- **Image Format:** 
  - PNG for screenshots and UI elements (lossless quality needed)
  - SVG for diagrams, flowcharts, technical illustrations (scalability needed)
  - JPG only if file size critical and slight quality loss acceptable (e.g., photo-realistic renders)
- **File Size Target:** 
  - Screenshots: <500KB (use PNG compression)
  - Diagrams (SVG): <100KB (optimized paths)
  - Renders: <800KB (balance quality and load time)
- **Compression:** 
  - PNG: Use tools like TinyPNG or pngquant for size reduction
  - SVG: Use SVGO for optimization
  - JPG: 85-90% quality setting if used
- **Responsive Sizing:** 
  - Images should work at 320px mobile width up to 1920px desktop
  - Consider providing 2x versions for retina displays
  - SVGs naturally responsive
  - Test at 768px (tablet), 1024px (small desktop), 1920px (full HD)

### Special Considerations for This Lesson
- **Bokeh visualization challenge:** Bokeh is subtle and requires high-quality renders to show properly. Use Cycles with high sample counts (512+) for bokeh examples. Consider showing exaggerated bokeh first (f/1.4, many background lights) then more subtle examples.

- **DoF in static images:** Depth of field is about blur, which is obvious in motion but can be subtle in stills. Ensure DoF comparison images have enough separation to make blur obvious. Use high-contrast subjects (dark vs light) and ensure background has detail that shows blur clearly.

- **Rack focus animation:** Since rack focus is temporal (happens over time), consider creating animated GIF or short video clip for Image #12 or #24 showing focus transition in action. If static images only, show clear before/middle/after composite.

- **Technical accuracy vs clarity:** Some DoF physics concepts (circles of confusion, hyperfocal distance calculation) are complex. Diagrams should simplify these concepts without being inaccurate. Focus on visual understanding over mathematical precision.

- **Blender interface consistency:** Ensure all UI screenshots use same Blender theme (dark) and same layout. Annotations should not obscure critical UI elements. Consider using Blender's built-in screencast keys if showing keyboard shortcuts.

- **Cross-referencing with other lessons:** This lesson builds on Lesson 20 (Camera Basics) and Lesson 21 (Composition). Consider visual consistency with images from those lessons. Use similar color coding and diagram styles for unified learning experience.
