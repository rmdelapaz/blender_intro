### **Rationale for SVG Recommendations:**

**Why these specific images benefit from SVG format:**

1. **Scalability:** Diagrams, flowcharts, and infographics need to look perfect at any size (mobile to 4K displays)
2. **Text Clarity:** Vector text remains razor-sharp at all zoom levels vs. rasterized text
3. **File Size:** Vector diagrams are typically 10-50x smaller than equivalent raster images
4. **Editability:** Easy to update text, colors, or layout without quality loss
5. **Accessibility:** Text in SVGs can be selected, searched, and read by screen readers
6. **Professional Appearance:** Crisp clean edges expected in educational/technical diagrams
7. **Web Performance:** Smaller files load faster, critical for online course materials

**Images that should remain raster (PNG/JPG):**

- Screenshots (Blender interface, actual viewport renders)
- 3D rendered characters and poses
- Photorealistic reference materials
- Motion blur examples
- Actual animation frames
- Before/after render comparisons

These require pixel-based rendering and benefit from raster formats.

## Notes

### **Style Consistency Guidelines**

**Color Palette (Use consistently across all images):**
- **Background (Blender/Dark UI):** #2b2b2b (dark grey)
- **Selection/Highlight:** #ff8c00 (bright orange)
- **Wireframe/Paths:** Cyan (#00BCD4) or white (#FFFFFF)
- **Normals/Technical:** Bright blue (#2196F3)
- **Success/Correct:** Green (#4CAF50)
- **Warning/Incorrect:** Red (#F44336)
- **Primary Actions:** Purple gradient (#667eea to #764ba2)
- **Text on Dark:** White (#FFFFFF) or light grey (#E0E0E0)
- **Backgrounds (Diagrams):** White or very light grey (#F5F5F5)

**Blender Version Consistency:**
- Use Blender 4.0+ interface for all screenshots
- Maintain consistent UI theme (dark theme recommended)
- Show version-appropriate features only

**Typography:**
- **Headers/Titles:** Bold sans-serif (Inter, Roboto, or similar)
- **Body Text/Labels:** Regular sans-serif
- **Annotations:** Clear, highly legible at small sizes
- **Minimum readable size:** 12pt for body text in diagrams

**Annotation Style:**
- **Arrows:** Simple single-line arrows, orange (#ff8c00) color
- **Callout boxes:** Semi-transparent dark backgrounds (rgba(0,0,0,0.7)) with white text
- **Highlight boxes:** Orange borders (#ff8c00), 2-3px width
- **Labels:** Positioned to not obscure important content

**View Angles for 3D Content:**
- **Default camera perspective:** 3/4 view (45-degree angle)
- **Technical diagrams:** Side view or top view when showing specific mechanics
- **Character poses:** Angle that shows best silhouette
- **Consistent horizon line** across similar images

**Lighting for 3D Renders:**
- **Key light:** Soft, 45-degree angle from front
- **Fill light:** Softer, opposite side
- **Rim/back light:** Separates character from background
- **Environment:** Simple HDRI or 3-point setup
- **Avoid harsh shadows** that obscure animation

### **Accessibility Considerations**

**Text Legibility:**
- Minimum contrast ratio: 4.5:1 for normal text, 3:1 for large text
- Avoid pure black on pure white (harsh contrast)
- Use sufficient font size (minimum 12pt for smallest text)
- Ensure text doesn't rely solely on color for meaning

**Color Blindness Considerations:**
- Don't rely solely on red/green for differentiation
- Use shapes, patterns, or labels in addition to color
- Test key diagrams with colorblind simulation tools
- Use high contrast color pairs

**Alternative Text Descriptions:**
- All images should have clear, descriptive filenames
- Complex diagrams should be accompanied by text descriptions in lesson
- SVG diagrams should include semantic markup where possible

**Screen Reader Compatibility:**
- SVG text should be actual text, not paths
- Important information shouldn't be conveyed by image alone
- Diagrams should have text equivalents in HTML

### **Technical Specifications**

**Screenshot Resolution:**
- Minimum: 1920x1080 (Full HD) for interface screenshots
- Viewport screenshots: 1920x1080 or higher
- Reference materials: 1920x1080 minimum
- Can go higher (2K/4K) for detail, but ensure web-optimized versions exist

**Image Formats:**
- **PNG:** Screenshots, diagrams with transparency, reference materials
  - Use 24-bit color (no palette)
  - Compression level: 6-9 (balance size/quality)
- **SVG:** All pure vector diagrams, flowcharts, infographics
  - Optimize paths, remove unnecessary metadata
  - Embed fonts or convert to paths
- **JPG:** Only for photographic content if file size is concern
  - Quality: 85-90% (avoid visible compression artifacts)
  - Progressive encoding for web

**File Size Targets:**
- Screenshots (PNG): 200KB - 1MB per image
- Diagrams (SVG): 50KB - 200KB
- Reference sheets (PNG): 500KB - 2MB
- Optimize all images before final delivery using tools like:
  - TinyPNG for PNG optimization
  - SVGOMG for SVG optimization
  - ImageOptim for batch processing

**Responsive Sizing:**
- Images should display well at:
  - Mobile: 320px - 768px width
  - Tablet: 768px - 1024px width
  - Desktop: 1024px+ width
- Consider providing multiple sizes or using responsive images
- SVG diagrams scale perfectly (major advantage)

**Animation-Specific Requirements:**
- Motion blur and dynamic movement need special attention in stills
- Use motion arrows or sequential frames to show movement
- Frame numbers must be clearly visible in timing examples
- Graph editor screenshots need high contrast for curve visibility

**Character Variety:**

**Professional Standards:**

- Match quality standards of commercial animation courses

**Versioning and Updates:**
