**SPEC CORRECTION (#12, 2026-06-23) &#8212; I-key no longer shows a menu in Blender 5.1.** The requirements-doc #12 was specced against pre-4.1 Blender where pressing **I** in the viewport popped the Insert Keyframe Menu. In Blender 4.1+ (confirmed 5.1.1) the I key was redesigned: it **directly inserts** keyframes on the default channel set (preference `edit.key_insert_channels` = LOCATION / ROTATION / SCALE / CUSTOM_PROPS) with **no popover**. The old menu is gone from the default keymap. Pressing I over the viewport with an object selected silently keys all transform channels at the current frame; pressing it over the Timeline/Properties (wrong editor) does nothing, and pressing it with nothing selected does nothing &#8212; which is what made it look broken. The canonical 5.x "insert keyframe menu" is now the **right-click Object Context Menu** (that is #13) or a right-click on a transform field. Per Ray, #12 was re-pointed to show the **I-key RESULT** (before: unkeyed; after: keys on all 9 transform channels), which is scriptable (no popover, no Win+Shift+S) and the most honest 5.1 representation. Slug changed `insert_keyframe_menu` &#8594; `insert_keyframe_result`. This also moved #12 OUT of the Win+Shift+S Ray-drives batch.
