## Notes

### Style Consistency Guidelines

**Color Palette (Standard for All Images):**
- Background: Dark grey (#2b2b2b) - matches Blender's dark theme
- Primary accent: Bright orange (#ff8c00) - for emphasis, selected elements
- Secondary accent: Cyan (#00bfff) - for motion paths, secondary elements
- Success/Good: Green (#4CAF50) - for correct examples, checkmarks
- Warning/Error: Red (#f44336) - for incorrect examples, X marks
- Neutral: White (#ffffff) - for text, labels, measurements
- Wireframe: Light cyan (#88ddff)

**Typography:**
- Headers: Bold, sans-serif (Arial, Helvetica, or similar)
- Body text: Regular sans-serif, minimum 14pt for readability
- Labels: All-caps for major headings, sentence case for descriptions
- Annotations: Italic for explanatory notes

**Annotation Style:**
- Arrows: Solid lines with arrowheads, consistent thickness (3-4px)
- Callouts: Rounded rectangles with pointer arrows
- Emphasis circles: Dashed or solid rings, 4-5px thickness
- Measurement lines: Thin solid lines with perpendicular end caps

**Blender Version:** Use Blender 4.0 interface appearance for all Blender screenshots to maintain consistency with course material

**View Angles:**
- Side view (orthographic) for bounce trajectories and motion arcs
- 3/4 perspective for general viewport screenshots
- Top-down for spatial relationship diagrams

**Selection Highlighting:**
- Selected objects: Bright orange (#ff8c00) outline
- Active elements: Glowing effect or thicker outline
- Comparison elements: Side-by-side with clear visual separation

### Accessibility Considerations

**Color Blindness:**
- Never use color alone to convey information
- Pair red/green comparisons with symbols (✓/✗) or labels ("Good"/"Bad")
- Use patterns or textures in addition to color coding
- Ensure sufficient contrast ratios (WCAG AA minimum: 4.5:1 for text)

**Text Readability:**
- Minimum font size: 14pt for body text, 18pt for headers
- High contrast text (white on dark, never grey on grey)
- Avoid text over busy backgrounds
- Use text shadows or outlines when text overlays images

**Alternative Text Preparation:**
- Each image should have descriptive alt text prepared
- Describe content, not appearance ("Graph showing bounce height decay over three bounces" not "Line graph with orange dots")
- Include data values in alt text for charts/graphs

**Diagram Clarity:**
- Avoid overcrowding - better to have two simple diagrams than one complex one
- Ensure adequate spacing between elements
- Use clear visual hierarchy (size, weight, color)
- Label all elements explicitly - don't assume visual recognition

### Technical Specifications

**Screenshot Resolution:** 
- Minimum 1920x1080 for full-interface screenshots
- 1600x900 for focused panel screenshots
- Higher resolution (2560x1440) preferred for crisp detail at reduced display sizes

**Image Formats:**
- **PNG:** Screenshots, composites, diagrams with transparency, anything requiring lossless quality
- **SVG:** Simple diagrams, infographics, charts, reference cards, technical illustrations
- **JPG:** Photo references only (if any), never for screenshots or diagrams

**File Size Targets:**
- SVG: Keep under 100KB (optimize paths, remove unnecessary nodes)
- PNG: Aim for under 500KB (optimize with tools like TinyPNG while maintaining quality)
- Maximum 1MB per image absolute limit

**Compression:**
- PNG: Use lossless compression tools (OptiPNG, TinyPNG)
- SVG: Minify and remove unnecessary metadata
- Maintain visual quality - compression shouldn't degrade educational value

**Responsive Sizing:**
- Design for 1920px width maximum (desktop)
- Ensure legibility when scaled to 768px width (tablet)
- Consider mobile viewing (320px width minimum) - text must remain readable
- Test critical diagrams at multiple sizes
