## Notes

### Style Consistency Guidelines
- **Color Palette:** 
  - Background: Dark grey #2b2b2b (matches Blender default dark theme)
  - Particle highlight: Bright orange #ff8c00 (high visibility)
  - Emitter objects: Medium grey #666666
  - Wireframes: Cyan #00d4ff
  - Annotation text: White #ffffff
  - Selection/emphasis: Bright orange #ff8c00
  
- **Blender Version:** All screenshots should reflect Blender 4.0+ interface for consistency
- **View Angles:** Use standard orthographic views (front, side, top) for technical diagrams, 3/4 perspective for beauty shots
- **Selection Highlighting:** Bright orange outlines for selected elements, consistent across all images
- **Typography:** Clean sans-serif fonts (Roboto, Open Sans) for labels, sufficient contrast for readability
- **Annotation Style:** White arrows and lines, semi-transparent dark boxes for labels

### Accessibility Considerations
- **Alt Text Requirements:** Every image must have descriptive alt text explaining visual content
- **Color Contrast:** All text overlays maintain 4.5:1 minimum contrast ratio with backgrounds
- **Text Size:** Minimum 14pt font size for diagram labels, 16pt for primary annotations
- **Non-Color Indicators:** Use shapes and patterns in addition to color for differentiation
- **Screen Reader Friendly:** Diagram logic flows left-to-right, top-to-bottom for natural reading

### Technical Specifications
- **Screenshot Resolution:** Minimum 1920x1080 for full-frame shots, scale appropriately for panels
- **Image Format:** 
  - PNG for screenshots, rendered images, and composites (supports transparency, lossless)
  - SVG for pure diagrams and flowcharts (scalable, editable, small file size)
  - JPG only if file size is critical concern and no transparency needed
- **File Size Target:** 
  - Screenshots: Under 500KB (optimize with PNG compression)
  - Rendered images: Under 800KB (balance quality vs. size)
  - SVG diagrams: Under 100KB (keep paths simple)
- **Compression:** Use lossless PNG compression tools, maintain visual quality
- **Responsive Sizing:** Images should scale well from 320px mobile to 4K displays

### Special Considerations for This Lesson
- **Motion Visualization:** Several images need to show particle motion/trajectories. Use motion blur, trails, or arrow overlays to convey movement in static images
- **Temporal Elements:** Particle lifetime and emission timing are time-based. Multi-frame sequences or timeline diagrams help convey these concepts
- **3D Spatial Relationships:** Particles exist in 3D space. Use multiple views, depth cues, and clear perspective to show spatial relationships
- **Settings Correlation:** Many images should show both the settings panel AND the resulting effect for clear cause-effect relationship
- **Before/After Comparisons:** Particle effects are often about subtle differences (with/without turbulence, different gravity values). Split-screen comparisons are very effective
- **Interactive Elements:** Consider annotating where users should click, what values to adjust - guide them through the interface

### Production Notes
- **Blender Scene Setup:** 
  - Create template .blend file with standard lighting setup (soft area light, neutral grey world)
  - Save viewport shading presets for consistency (material preview for color, solid for technical)
  - Set up default camera angles for each shot type (overhead, side view, 3/4 perspective)
  
- **Lighting Setup:** 
  - Viewport lighting: Use Blender's default studio lighting for consistency
  - Rendered shots: Three-point lighting or simple HDRI for natural look
  - Dark backgrounds preferred (match lesson aesthetic)
  
- **Camera Angles:** 
  - Technical diagrams: Orthographic view, aligned to grid
  - Interface screenshots: Straight-on perpendicular view
  - Beauty renders: 3/4 perspective, dynamic composition
  
- **Batch Processing:** 
  - Create particle system templates for common effects (rain, snow, sparks)
  - Reuse base scenes where possible to maintain visual consistency
  - Use Blender's render layers to efficiently produce variations
  
- **Version Control:** 
  - Keep .blend source files organized by image number
  - Save incremental versions when making significant changes
  - Document any custom settings or non-standard techniques
  
- **Template Reuse:**

  - Annotation overlay templates for consistent labeling style
