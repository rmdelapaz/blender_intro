### Production Method Recommendations:

**For SVG Diagrams (Images #1, 2, 8, 17, 21, 22, 25, 31):**
1. Generate initial version with AI using provided prompts
2. Trace/recreate in vector software (Inkscape, Illustrator) for true SVG
3. Export as both SVG (for web) and PNG (backup)
4. Optimize SVG files for web (remove unnecessary metadata)

**For Screenshots/UI Images (Images #5, 10, 26, 29, 30, 34):**
1. Capture directly from Blender 4.0 (most accurate)
2. Use consistent viewport settings (same lighting, background)
3. Annotate in image editor (Photoshop, GIMP, Krita)
4. Save as PNG with transparency where appropriate
5. Optimize for web (compress without quality loss)

**For Step-by-Step Guides (Images #14, 15, 30):**
1. Create clean Blender scene for each step
2. Capture each step consistently (same camera angle)
3. Composite in image editor with numbered panels
4. Add captions and annotations
5. Ensure readability at smaller sizes

**For Composites/Comparisons (Images #2, 9, 11, 16, 18, 23, 24, 27, 28, 32, 33):**
1. Generate or capture individual elements
2. Composite in image editor for side-by-side or grid layouts
3. Use consistent backgrounds and lighting
4. Add clear labels, checkmarks/X marks for good/bad
5. Ensure equal spacing and alignment

**For Beauty Shots (Images #35, 38):**
1. Setup clean Blender scene with professional lighting
2. Use Cycles for high-quality render if needed
3. Capture from multiple angles
4. Post-process for portfolio quality
5. Add subtle annotations if needed

## Notes

### Style Consistency Guidelines

**Color Palette Standards:**
- **Background:** Dark grey (#2b2b2b) for all viewport/diagram backgrounds
- **DEF bones:** Purple (#667eea) - deformation layer
- **MCH bones:** Blue (#2196F3) - mechanism layer
- **FK controls:** Orange (#ff8c00) - forward kinematics
- **IK controls:** Cyan (#00bcd4) - inverse kinematics
- **Left side:** Blue/Cyan (#00bcd4) - left arm/leg controls
- **Right side:** Red/Magenta (#e91e63) - right arm/leg controls
- **Center controls:** Yellow/Green (#ffd600) - root, COG, chest
- **Selection highlight:** Bright orange (#ff8c00) - active selections
- **Success indicators:** Green (#4CAF50) - checkmarks, correct examples
- **Warning/Error:** Red (#f44336) - X marks, incorrect examples
- **Annotations:** White text (#ffffff) with semi-transparent dark backgrounds for readability

**Blender Version Consistency:**
- All screenshots: Blender 4.0 interface
- Dark theme throughout
- Consistent viewport shading mode
- Same camera angles for similar shots
- Unified control sizes across images

**Typography Standards:**
- **Headers:** 24-32pt, Bold, Sans-serif
- **Body annotations:** 16-20pt, Regular, Sans-serif
- **UI labels:** 14-16pt, matching Blender's UI font
- **Captions:** 14-18pt, Italic or Regular
- **Always:** High contrast text (white on dark, dark on light)

**Annotation Style:**
- **Arrows:** Consistent style (same thickness, same arrowhead)
- **Leader lines:** Thin, white or contrasting color
- **Callout boxes:** Semi-transparent backgrounds behind text
- **Highlight boxes:** Bright outline (orange, cyan) around important areas
- **Numbering:** Circles with numbers for sequential steps

**Layout Standards:**
- **Margins:** Consistent padding around canvas edges
- **Grid layouts:** Equal spacing between cells/panels
- **Split-screens:** 50/50 or 60/40 ratios (not arbitrary)
- **Title placement:** Top-center or top-left consistently
- **Captions:** Below images, centered or left-aligned consistently

### Accessibility Considerations

**Color Blindness:**
- Don't rely solely on color to convey meaning
- Use shapes, patterns, labels in addition to colors
- Test with color blindness simulators
- Provide text alternatives in captions

**Contrast:**
- Minimum 4.5:1 contrast ratio for text
- Use high-contrast annotation colors
- Avoid low-contrast color combinations (gray on gray)

**Text Size:**
- Minimum 14pt for body text in diagrams
- All text readable at 1080p resolution
- Consider that images will be viewed at various sizes

**Screen Reader Compatibility:**
- Provide meaningful alt text for all images (in HTML)
- Diagrams should have text descriptions of relationships
- Don't put critical info only in images

**Visual Clarity:**
- Avoid cluttered compositions
- One concept per image when possible
- Clear visual hierarchy (important elements larger/brighter)
- Sufficient white space around elements

### Technical Specifications

**Resolution Standards:**
- **Primary format:** 1920x1080 (16:9) for most images
- **Portrait format:** 1200x1600 for UI panels/tall diagrams
- **Wide format:** 1920x480 for sequential timelines
- **Square format:** 1000x1000 for icons/simple diagrams
- **Higher res option:** 2560x1440 for beauty shots

**File Format Guidelines:**
- **SVG:** For diagrams, flowcharts, simple illustrations
  - Optimize and compress
  - Remove unnecessary metadata
  - Keep file sizes under 200KB
  
- **PNG:** For screenshots, composites, step-by-steps
  - 24-bit color depth (millions of colors)
  - Use transparency when beneficial
  - Compress with pngquant or similar (target <500KB per image)
  
- **JPG:** Only if PNG file size is excessive
  - Use quality 85-90 (balance quality/size)
  - Not for images with text (PNG is better)

**Compression:**
- Optimize all images for web delivery
- Target: <500KB per image for PNG
- Target: <300KB per image for JPG
- SVG should be <200KB (usually much smaller)
- Use lossless compression when possible

**Responsive Considerations:**
- Images should be readable at 50% scale (mobile)
- Text should remain legible at smaller sizes
- Consider providing 2x versions for high-DPI displays
- Ensure images work in both light and dark themes (if applicable)

### Special Considerations for This Lesson

**Rigging Complexity:**
- Lesson has high technical density (many concepts)
- Images must simplify without oversimplifying
- Balance between completeness and clarity
- May need to break complex images into multiple simpler ones

**3D Spatial Relationships:**
- Rigging is inherently 3D (bones in space)
- 2D images must convey 3D relationships clearly
- Use multiple viewing angles (top, side, perspective)
- Isometric or 3/4 view often best for spatial clarity

**Hierarchical Information:**
- Parent-child relationships are critical
- Use clear hierarchy lines and tree diagrams
- Color-code layers and connection types
- Consistent visual language for "parents to" vs "controls"

**Before/After Sequences:**
- Many concepts best shown as progressions
- Consistent framing across sequence frames
- Clear indicators of what changed between frames
- Use arrows or highlights to guide eye

**Abstract Concepts:**
- IK/FK switching, blending, drivers are abstract
- Need concrete visual metaphors
- Use gradients, percentages, graphs to show blending
- Make invisible relationships visible
