## Notes

### Style Consistency Guidelines

**Color Palette Standards:**
- Blender Interface: Dark grey (#2b2b2b) for backgrounds
- Selection Highlights: Bright orange (#ff8c00) for active/selected elements
- Wireframe: Cyan or white for geometry in viewport
- UI Annotations: White text with semi-transparent dark background for readability
- Success/Correct: Green (#4CAF50)
- Warning/Problem: Red (#f44336)
- Information: Blue (#2196F3)

**Blender Version:**
- Use Blender 4.0 or 4.1 interface for consistency
- Dark theme (default) for all screenshots
- Ensure interface elements are clearly visible and labeled

**Typography:**
- Sans-serif fonts (Arial, Roboto, or similar) for all labels
- Minimum 14pt font size for readability when scaled down
- White text with dark outline or background for visibility over images
- Consistent label positioning (typically bottom or side of panels)

**Annotation Style:**
- Orange circles or arrows (#ff8c00) to highlight specific UI elements
- White text for explanatory labels
- Semi-transparent dark boxes behind text for readability
- Arrows should be clean and professional, not hand-drawn style
- Use consistent arrow thickness and style throughout all images

**Photorealism Standards:**
- For architectural renders: Aim for "could be mistaken for photograph" quality
- Natural lighting with proper sun + HDRI setup
- Realistic materials with subtle imperfections
- Proper camera angles following architectural photography principles
- Context elements (landscaping, sky) always included

### Accessibility Considerations

**Color Blindness:**
- Don't rely solely on color to convey information
- Use labels, patterns, or shapes in addition to color coding
- High contrast between text and background (minimum 4.5:1 ratio)
- Avoid red/green combinations as sole differentiators

**Text Readability:**
- Minimum 14pt font size in images
- High contrast text (white on dark, or dark on light)
- San-serif fonts for clarity
- No text smaller than would be readable at 800px width

**Alternative Text Descriptions:**
- Each image should have descriptive alt text in HTML
- Alt text should convey the educational content, not just describe appearance
- Example: "Diagram showing three levels of window modeling detail from simple plane to fully detailed frame with mullions"

### Technical Specifications

**Screenshot Resolution:**
- Minimum 1920x1080 for full-width screenshots
- 2560x1440 preferred for high-detail interface captures
- Viewport renders: 1920x1080 minimum for clarity
- Interface panels: Capture at native resolution, scale down 50% max

**Image Formats:**
- PNG for:
  - Screenshots with UI elements (lossless, supports transparency)
  - Diagrams with text and sharp edges
  - Composites with multiple panels
  - Images requiring transparency
- SVG for:
  - Flowcharts and workflow diagrams
  - Technical dimension references
  - Grid overlays and measurement guides
  - Any purely vector content
- JPG for:
  - Photorealistic renders (smaller file size acceptable)
  - Reference photos without transparency needs
  - Quality setting: 90-95% to balance quality and file size

**File Size Targets:**
- PNG screenshots: 500KB - 2MB typical
- SVG diagrams: 50-200KB typical
- JPG renders: 300KB - 1MB typical
- Maximum any single image: 3MB (compress if larger)

**Compression:**
- PNG: Use PNG compression tools (pngquant, TinyPNG) for 30-50% size reduction
- JPG: Quality 90-95% strikes balance between size and quality
- SVG: Optimize with SVGO to remove unnecessary data

**Responsive Sizing:**
- Images should scale well from 320px (mobile) to 1920px (desktop)
- Ensure text remains readable at 800px width
- Test critical UI screenshots at various sizes
- Provide high-resolution originals (2x) for retina displays
